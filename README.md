# Piecebook

Phone-first web app for One Piece TCG collectors. V1 lists every EN booster set on Cards' roster with its box priced daily, lets you search every set at once by name or number (a full number opens the card), browse every set's EN checklist by rarity, search a set by name or number, sort by name or seed price, read a short intro per set, see every print of a character across sets, see which sealed product feeds each set, mark the cards you own, log what you paid, and see a seed-priced portfolio.

Specs live alongside the code: `V1-PRD.md` (scope), `V1-DESIGN-PACK.md` (IA, palette, copy), `docs/V1-DESKTOP-LAYOUT.md` (tablet/desktop breakpoints), `docs/V1-SETTILE-AND-GRID-PRICES.md` (sealed box prices on set tiles, seed price and week move on set-detail cells), `docs/V1-OWN-AND-SET-DEPTH-UI.md` (set intro, thin Own), `docs/V1-SET-DETAIL-CONTROLS.md` (search, sort, All tab), `docs/V1-COST-AND-PORTFOLIO-UI.md` (cost basis, Portfolio), `docs/WATCHLIST.md` (target prices), `docs/V1-SETS-ROSTER-UI.md` (full EN roster, pending set detail), `docs/V1-MOVERS-COMPLETION-PLAYSETS-UI.md` (movers, change since starred, set completion, playsets), `docs/V1-BOX-CARD-AND-ART-UI.md` (the box as a product card, box art), `docs/V1-DECKS-UI.md` (decks: the fourth tab, the builder, the collection gap, legality), `docs/V1-STARTER-DECKS-LINKS-LEARN-UI.md` (starter decks, the Limitless link, learn to play), `docs/V1-CUSTOMER-LENSES-UI.md` (Start here in visitor language, with existing box and card art), `docs/V1-FIND-UI.md` (search facets, artists, characters, upcoming sets), `docs/V1-BELONG-UI.md` (set stories, the release timeline, Start here), `docs/V1-FANDOM-UI.md` (wiki who-is line, On This Day, countdown; Today's card stood down), `docs/V1-FANDOM-PAGE-UI.md` (`/belong`, fifth tab World, story index, fruit log, people book, reader cutoff), `docs/V1-CURRENCY-AND-HEALTH-UI.md` (Portfolio S$ at the dated ECB cross; Data health), `docs/V1-PREGRADE-UI.md` (pre-grade + grade-worth: centering, typed pops/solds, prediction log), `seed-sources.md` (data provenance), `docs/HANDOFF.md` (how this project is run, for a fresh session).

## Run it

```bash
npm install
npm run dev
```

Open the printed URL (default `http://localhost:5173`). Below 768px the app is a phone column with a bottom tab bar (Sets · Decks · Portfolio · World); from 768px up it grows to a 720 / 1100 / 1280px column with a quiet top bar and a 3–5 column card grid (see `docs/V1-DESKTOP-LAYOUT.md`).

```bash
npm run build     # type-check + production build into dist/
npm run preview   # serve the production build locally
npm test          # centering (±2 points on known ratios) and grade-worth (5 cases)
```

## Data

- **Catalog** is the read-only seed under `data/`: one `{code}-en-seed.csv` per roster set (58 files: 23 booster sets and 35 starter decks, 4,083 rows; see `docs/seed-sources.md`). Every `*-en-seed.csv` is picked up by `import.meta.glob`, bundled into its own `seed` chunk at build time and parsed in the browser. Regular sets load same-set numbered rows only (a row's `card_number` must carry its `set_code`, e.g. `OP17-001` under `OP-17`); PRB premium boosters and ST starter decks are reprint products and list every print in the box, so a card has one home set but can also appear in a PRB or ST checklist. See `data/SEED-VERSION.txt`. Adding a set is a CSV drop-in plus flipping its roster row to `ready`.
- **Prices** are the seed `market_usd` values with their `as_of` date. There is no live price feed; every price in the UI is labelled as seed. Card cells show the seed price in ink under the name; on set detail they also show the week move in dollars and percent when two dated points exist. Card detail carries the `as_of` date.
- **Parallels** are detected from the card number (`OP09-001p1`) and shown in their own Parallels tab; the All tab includes them too. Each parallel carries a human `variant` name from Limitless ("Alternate Art", "Manga Art", "Special Card", …) shown after the card name; the number stays visible.
- **Decks** run on the same card attributes: when a Decks screen opens, every set's attributes load (about 100 kB gzipped over the 23 per-set chunks) so the builder can tell colours, categories and Standard / Extra legality for any card; the main bundle is unchanged. Deck rules are Bandai's: one leader, exactly fifty, four copies of a number (a parallel is the same card), colours matching the leader, no leader in the fifty; nothing else is inferred.
- **Card attributes** live in `data/card-attributes/{code}.csv` (category, colour, cost / life, power, counter, attribute, traits, effect and trigger text, illustrator, regulation block, Standard / Extra legality), written by the same refresh and loaded lazily per set on card detail (`src/data/attributes.ts`). They feed the Play block and the `Illustrated by` line. Card text is Bandai's, shown as every card database shows it (accepted 5 Sep 2026); bracketed keywords such as `[On Play]` get a little weight, the words are unchanged. Where Limitless has no value (a blank, a `?`, or an untranslated `card.*` key) the line is omitted; nothing is inferred. 282 prints have no effect text and show none; 859 have no artist credit.
- **Data health** is `data/health.json`, written by the same refresh: counts, named unpriced prints, named exclusions. The `/data` page is the weekly read. `seed:check` warns if the file is more than 8 days old.
- **Wiki lines** come from `data/wiki/lines.json`, written by `npm run wiki:refresh` (`scripts/wiki-refresh.mjs`): One Piece Wiki text, CC BY-SA 3.0, two parse calls per Character or Leader name, never an image. Each entry carries the wiki title, a revid permalink, a birthday when the Char Box parsed one, a spoiler-gated first sentence (debut-arc cutoff), and the cleaned clauses. A redirect that adds a later name (`Imu` → `Nerona Imu`) is a reveal and the app shows nothing. First cache 6 Sep 2026: OP-01, OP-09, OP-17 and every leader (214 asked, 188 mapped, 40 lines, 169 births). `seed:check` fails a line over 22 words and warns after three silent days. See `docs/seed-sources.md`.
- **Wiki belong rooms** come from `data/wiki/summaries.json` and `data/wiki/fruits.json`, written by `npm run wiki:belong`. The story file is an index: 33 main-arc titles and chapter/episode ranges on the wiki Story Arcs page — no plot paragraph. Fruits are Char Box first-line names on mapped printed names (92 fruits, 6 Sep 2026); later-names after a line break (Nika) and Imu / The Devil's Fruit are not stored. Wiki images are never pulled; wiki article links are never rendered. `seed:check` fails a missing licence, a stored plot paragraph, a localizer credit in a fruit name, or Imu as an eater.
- **Set intros** come from `data/set-intros.json`: for every set the EN release date (Bandai EN product page), JP release date and Japanese title (Bandai JP product page), Bandai's EN card-types count, and packs-per-box / cards-per-pack where Bandai states them. Missing fields are simply omitted; nothing is inferred. **Set stories** (7.1) are the one piece of authored copy per set: `introTheme`, one sentence of ours written from the Bandai EN product page named in `introSource` (Bandai's EN card list for EB-04 and OP-17, which have no EN page; OP-18 has no line yet), never quoted, at most 22 words, present tense, no rarity / alt-art / campaign / anniversary words, no superlatives, and naming every one of the set's leaders or none. The refresh never writes one; `seed:check` warns on a ready set without a line and fails a line that breaks a rule. The story shows on the set page only, under the set's name.
- **Search and sort** on Set detail run in the browser over the seed. Search matches name or number (`004`, `op09-004`, `OP09-004`). Sort is Price high to low (default), Price low to high, Name A to Z, Name Z to A; cards without a seed price sort last. Search and sort live in the URL as `?q=` and `?sort=`. Each cell shows the seed price in ink and, on the set page, the week move in dollars and percent (`−$15.99 (−5.54%)`) when two dated points exist.
- **Global search** on Sets home (`src/lib/search.ts`) parses facets first (`parseQuery`: colours, types, cost, traits, keywords via `hasKeyword`, owned/missing; attributes load once on first search and are cached) and then runs the same name-or-number match over every distinct card once (3,301; a PRB reprint of a home-set card is one card, a PRB-only parallel has PRB as its home set). Results are grouped by home set in roster order; a name that recurs in more than one set is listed under “Across sets” with its print and set counts and links to the character view. A query that is a full card number — hyphens, spaces and case forgiven (`OP09-118`, `op09 118`, `op09118`, `op09-004p1`, `P-014`) — resolves to that card: an “Open” row appears and Enter opens it. Under two characters nothing is searched (“Keep typing to search every set.”). Nothing is indexed ahead of time; 3,301 cards filter in under a millisecond per keystroke.
- **Sealed guidance** (the EN / JP box lines on set detail) is derived in `src/data/sealed.ts` from the intro dates and JP title: `Box feeds this set · 13 Dec 2024` / `Box (新たなる皇帝) · 31 Aug 2024`. EB-04 overrides the EN line because it has no EN box.
- **Sealed prices and box art** are automated (decision 3.1 and the box-card addendum, 5 Sep 2026). Every EN booster box's TCGplayer market price is pulled once a day by the refresh from [TCGCSV](https://tcgcsv.com), a public daily mirror of TCGplayer's own API, into `data/box-price-history.csv` (`set_code,as_of,market_usd,low_usd,source`); tiles and the box card show the newest row with its date, and from the second day the movement since. Each roster row names its box by `tcgplayerProductId` / `tcgplayerGroupId`; the same id gives the box image, TCGplayer's official product render, hotlinked from their CDN like card art from Limitless's (`…/product/{id}_400w.jpg` on tiles, `_in_1000x1000.jpg` on the card). Nothing is vendored or hand-read any more; the roster's own `usMarketUsd` / `asOf` are a fallback only and its `sgAskSgd` values are kept as provenance but not shown. `seed:check` warns if the feed goes quiet for 3 days.
- **Sets roster** is `data/sets-roster-en.json` (Cards): `{ asOf, note, sets }` with the 23 EN sets (OP-01…OP-17, EB-01…04, PRB-01…02; EB-04 has no EN box and carries null prices), each with `product: booster_box`, EN release date, `cardSeedStatus` (`ready` / `pending`), the EN booster box TCGPlayer US market price with its `asOf` date and `usSource` URL (all 22 sets), an SG ask only where verified (OP-09, OP-16), and optional box art. The roster decides which tiles appear on Sets home and in what order; the card CSVs only decide whether a set has a browsable checklist. `boxArtUrl: "vendored"` means “use the front already under `public/box-art/`”; anything that is not a local path is treated as no art.
- **Price history** is `data/price-history/{code}.csv` (`card_number,as_of,market_usd,source`, one row per card per day). Two sources, both labelled on the chart: `limitless` rows are the daily seed readings from `npm run seed:refresh`; `tcgplayer` rows are a one-off backfill of about a year of weekly market prices from TCGPlayer's product-page chart data (`npm run seed:backfill`, keyed by `data/tcgplayer-products.csv`, approved 5 Sep 2026). Where both exist for a day the Limitless reading wins. History is loaded lazily per set on card detail only and drawn as a quiet line with 1M · 3M · 6M · 1Y · All range chips. There is still no live feed.
- **Refreshing the seed**: `npm run seed:refresh` (Node 18+, no dependencies) re-pulls every roster set from Limitless with the rules in `docs/seed-sources.md`, rewrites the CSVs, appends today's prices to the history and repins `data/SEED-VERSION.txt`. `--sets OP-17,EB-04`, `--dry-run`, `--as-of YYYY-MM-DD`, `--no-history`. It never edits Cards' roster JSON. `npm run seed:check` validates the data contract (headers, same-set rule, rarity codes, CDN-only images, no checklist gaps, pinned counts, one history row per card per day). Parsing all 23 CSVs at startup costs ~4 ms; the seed chunk is ~55 kB gzipped.
- **Automation** (`.github/workflows/`): `ci.yml` type-checks, builds and runs `seed:check` on every push to `main` and every pull request. `seed-refresh.yml` runs the refresh daily at 02:10 UTC (10:10 SGT), builds against the result and opens or updates one PR on the `automation/seed-refresh` branch for review; it can also be run by hand from the Actions tab with a set list or as a dry run. Nothing lands on `main` unreviewed. One-time repo setting: Settings → Actions → General → Workflow permissions → allow GitHub Actions to create pull requests.
- **Where the history comes from**: Piecebook's own daily readings began on 4 Sep 2026. There is no free historical feed (Collectr and PriceCharting hold years because they have snapshotted licensed TCGPlayer / eBay sales data daily for years; PriceCharting's API explicitly excludes history), so on 5 Sep 2026 Jib approved a single backfill from TCGPlayer's product-page chart endpoint, which gives roughly a year of weekly market prices per print. The daily workflow carries it forward from there. Details and the trade-offs in `docs/V1-WATCHLIST-AND-CHARTS.md`.
- **Movers and change since starred** reuse the dated seed points: the reference for a Week / Month mover is the newest point at least that old (with weekly backfill points that can be up to 13 days), so every figure carries its `since` date; a watched card's change is measured from the newest point on or before the day it was starred. Nothing is shown for cards without two dated points, and zero moves stay silent.
- **Playsets** count a card's owned copies against the four a deck may run (`2 of 4 for a playset`, `Playset complete`); leaders (rarity `L`) are one per deck and are left out.
- **Portfolio** is Piecebook’s own holdings book (see `docs/BOUGHT-SHEET.md`). Cost is the copy’s All-in SGD and is never converted. Market value is an English stored price for that print and grade (ungraded Limitless `market_usd` for raw; a PSA 10 or PSA 9 only when its printing is English), then the manual market value saved on the row, then “No price yet”. A Japanese OP Box Index median is not used. SGD for USD seed figures is the dated ECB cross in `data/fx-usd-sgd.json`. A PriceCharting URL is a click-through only and is not fetched. The phone shows `data/bought-fixture.csv` until a signed-in read of `/api/holdings` succeeds. Opening the screen records one totals row per UTC day in Cloudflare storage. The daily refresh pulls the ECB table; `seed:check` fails a missing rate or one older than 4 weekdays. Only the Cards agent writes holdings through the API. Auction routes a buy through Cards and does not call it. The Access service token is the one shared on the Linux box; a token write lands in the same book as Jib’s Access email.
- **Watchlist** is the target list (`docs/WATCHLIST.md`), not the star on a card. A row is one seed print id, a grade (Raw, PSA 9 or PSA 10) and an optional target in S$. `OP09-004 SP` is rejected; the error lists the print ids. The phone shows a fresh English stored price for that print, then a manual figure Cards typed, with its source and date, or “No price yet”. Piecebook does not fetch PriceCharting. `POST /api/watchlist/:id/price` sets the four manual fields in one call. A Japanese price is not used. A stale price is shown and is not a hit. The book starts empty. `externalId` can hold CH-001..CH-006 when Cards sends them. Cards adds a row through `POST /api/watchlist` and polls `GET /api/alerts` (there is no push). The service token writes `u:<OWNER_EMAIL>:watchlist.v1`, the same key as Jib’s phone. `WRITE_CLIENT_IDS`, when set, limits which service-token client ids may write.

## Your data is local-only

Owned flags, quantities and cost basis may still sit in the browser under `piecebook.v1`, one entry per card that was marked owned: `{ qty, ownedAt, cost?: { amount, currency: 'SGD' | 'USD', paidOn, note? } }`. Card lists do not read that key. **In your portfolio** is an `exactPrint` match. A code with no `exactPrint` is **You own a version** on every print of that card number. The key is not deleted. The deck builder and the first-visit check still read it. The watchlist (starred cards and sets) is stored separately under `piecebook.watchlist.v1`, and decks under `piecebook.decks.v1` (`{ decks: [{ id, name, leader, cards: { [baseNumber]: copies }, createdAt, updatedAt }] }`, base card numbers only). `piecebook.started.v1` records only that Start here has been seen. `piecebook.displayCurrency.v1` still stores `usd` or `sgd` from the old Portfolio chip; Portfolio is in S$ and does not read it. `piecebook.boughtAlerts.v1` remembers the last legal price that already fired an under-all-in alert on the sample book, on this device only. A signed-in dismiss is stored in Cloudflare instead (`u:<email>:alerts.v1`). The target list is a separate book (`u:<email>:watchlist.v1`), not these stars. `piecebook.readerCutoff.v1` remembers the World cutoff chip (`debut` … `now`; default `debut`). `piecebook.pregrade.v1` still holds older pre-grade drafts (numbers and verdicts, not the photos). The card page no longer shows or edits them. Clearing site data for the app wipes the local copy.

On the private Cloudflare deployment (see `docs/CLOUDFLARE-SETUP.md`) every one of those keys is also kept in the cloud behind Cloudflare Access, keyed by the signed-in email: the app loads from the cloud, writes through within a second, keeps `localStorage` as the offline cache, and settles conflicts per key by last write wins on an `updatedAt` stamp. **Your data** (linked from Portfolio) downloads a JSON backup of every key, imports one (with a confirm before anything is replaced), and shows the sync state. On a first login with an empty cloud copy the app offers a one-tap upload of what the device holds. The public GitHub Pages build has sync off and nothing is sent anywhere.

## Deploying

The build in `dist/` is a static single-page app. Configure your host to serve `index.html` for unknown paths so deep links like `/cards/OP16-001` work. Cloudflare Pages does this on its own as long as the build contains no `404.html` (a `/* /index.html 200` rule in `_redirects` is rejected as a loop and ignored), which is why the GitHub Pages bounce page lives in `.github/pages/` rather than `public/`. `.node-version` pins Node 22 for the Pages build; dashboard build variables are ignored while the root `wrangler.toml` exists.

**GitHub Pages** (`https://najibjuraimi-glitch.github.io/piecebook/`): `.github/workflows/pages.yml` builds every push to `main` with `PIECEBOOK_BASE=/piecebook/` (Vite `base`, the router `basename` and the box-art path all follow it), copies `.github/pages/404.html` into `dist/` so deep links load, and commits the result to the `gh-pages` branch. One-time repo setting: Settings → Pages → Build and deployment → Source "Deploy from a branch" → `gh-pages`, `/ (root)`. Locally the base stays `/`.

**Worker** (`worker/`, the photo check and cloud sync): `wrangler` is a root devDependency, so `npm ci` once at the repo root and then `npm run worker:deploy` (deploy), `npm run worker:dev` (local, on :8787 with on-disk KV), `npm run worker:tail` (live JSON logs) or `npm run worker:secret` (set `GEMINI_API_KEY`). Every script passes `--config worker/wrangler.toml`; there is no `package.json` in `worker/`. The photo check asks Gemini for short labels only (card number, language, rarity, variant, defect flags), never for the printed card text: transcribing it trips the model's recitation filter and the answer comes back empty. If the model still refuses, the Worker retries once with a number-and-language-only prompt and the app falls back to a typed card number with the photos kept for the card page.

## Not in V1

Live prices, invented FX rates (a Portfolio S$ market figure is a dated ECB reading, not a bank quote), player search facets (colour, category, cost, trait, effect — growth map 2.3, shipped), scanning, accounts or sync, marketplace or affiliate links, dark mode. The under-all-in line compares a stored legal price with the sheet’s all-in; it is not a live quote.
